Public pages only (project "Building blueprints" carousel, public unit page desktop `UnitFloorPlan` + phone `UnitPlanCard`). Data: `ProjectBlueprint.planRooms` (content/projects.ts) and `Unit.floorPlanRooms` (content/units.ts) = `PlanRooms {aspect, rooms:[{id,label,type,points 0..1}]}` — pure helpers in `lib/planRooms.ts` (`extractRoomsFromSvg`, `sanitizePlanRooms`, `roomSummary`).

**Auto-connect:** the SVG carries invisible markers `<polygon data-room="Kitchen" data-room-type="kitchen" points=… fill="none" stroke="none"/>` in `<g id="rooms">`. Read in the admin editor the moment the file is chosen (`components/admin/plan/BlueprintRoomsField.tsx`) AND server-side on save as a fallback (`features/planRooms/fromForm.ts`). The Blueprint AI prompt rule 12 tells an AI to emit them; the checker reports "N rooms found". Hand-marking (click corners, name, kind) is the manual path; both can be edited before saving.

**Public UI:** `components/plan/RoomPlan.tsx` — `RoomStage` (lift = clipped clone of the drawing scaled ~1.065 about the room centre with drop-shadow, `BOLDER` multi-drop-shadow filter for thicker lines, accent-tinted card, veil fades the rest; phones also glide-zoom to the room), `RoomPicker` (phone: counts line + chip row; PC: grouped column panel), keyframes `room-lift`/`room-tag-in` in globals.css. ProjectBlueprints' two-column layout must depend on ANY plan having rooms (not the visible slide) or the slider changes width mid-swipe and lands on the wrong slide.

**Not done:** the full-screen Lightbox shows the plain plan (no room lift); owner/client portal floor plans don't use rooms (they use the separate flat-highlight feature [[building-floor-plans]]). Demo: "Shopno Heights" public project + unit `shopno-heights-1a` via `scripts/seed-demo-real-plan.ts`.

**Update (user feedback, round 2):** (1) The room experience is ONE shared set of components (`RoomStage` / `RoomPicker` / `InteractiveRoomPlan` in `components/plan/RoomPlan.tsx`) and must be used in every place that shows rooms, now or later — public project blueprints, public unit page (phone `UnitPlanCard` + desktop `UnitFloorPlan`), AND the client app's Home card + full-screen viewer (tone `blue`/`paper`, `interactive={false}` inside the card button). Multi-select: "All rooms" / "All bedrooms 4" group buttons select a whole group at once (`toggleRoom`/`toggleGroup`). (2) A public unit whose uploaded plan is a WHOLE-FLOOR drawing shows ONLY that flat: `Unit.floorPlanFlat` (outline, from the editor or from the SVG's `data-flat` marker matching the unit number) + `unitPlanView()` frames/clips the plan to it and offers only rooms inside it. Client floor plans carry `BuildingFloorPlan.rooms`; `resolveUnitPlan` returns the rooms inside the owner's flat. (3) Uploaded blueprint SVGs are auto-fixed: `lib/svgNormalize.ts` turns a sideways drawing upright (direction read from the order of the outlined letters — word runs voting E/S/W/N), trims empty margins, wraps rotation in `<g data-bp-matrix>` (marker readers in `lib/planRooms.ts` apply it), idempotent via `data-bp-normalized`. Applied in `saveUploadedFile` (blueprint/normalize) and `prepareBlueprintFile` (CMS + floor plans) BEFORE markers are read. No lettering / unclear evidence = no auto-rotation; admin has Turn left/right/Flip buttons (`BlueprintRoomsField` client-side, floor-plan editor via `rotateFloorPlanImageAction`). Not yet verified in a real browser upload: the client-side DataTransfer file swap in `BlueprintRoomsField`.

**Update (round 5):** Two LEVELS of buttons from one drawing (`buildingLevel()` / `flatLevelRooms()` in lib/planRooms.ts): the PUBLIC PROJECT page's building blueprints offer building-level things only — Flat A/B/C, Lift, Stair, Lobby, other shared spaces ("Show all" group); rooms (bedroom, kitchen, servant room…) belong to a flat's own plan (public unit page, client flat page). New room types: flat, servant, store, lift, stair, lobby. Admin marking is one press: preset buttons (`FLAT_PRESETS` for flats' rooms, `BUILDING_PRESETS` for project blueprints; `BlueprintRoomsField preset="flat"|"building"`; floor-plan editor has + Flat / + Parking bay / + room presets) with auto naming via `nextAreaLabel` (Bedroom 1, Bedroom 2…, Flat A, B…, P-01, P-02…) and a Box (2 clicks) vs Shape drawing mode. Client flat page (`PropertyFloorPlan`): card = whole floor, buttons only GLOW (`zoomOnSelect={false}`, card not interactive), tap card → full screen showing ONLY the owner's flat (`frame`) where the same buttons zoom in. Home remembers the chosen flat in cookie `sb_home_flat` (lib/homeFlat.ts, read server-side in OwnerHomePage so there is no flash). With nothing marked, plans stay the plain SVG exactly as before.
